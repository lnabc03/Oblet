## 一、核心结论

**一期（深/浅框架 + AnuPpuccin 适配）技术可行性极高。** 当年静态打包的 `src/styles/anuppuccin-custom.css`（9080 行）完整保留了全部 6 个 Catppuccin flavor 的浅色变量块（`.theme-light.ctp-latte`:2704、`.theme-light.ctp-rosepine-light`:2733 等 88 处明暗选择器），只是 `index.html:47` 把 body 类写死为 `theme-dark`，浅色规则全部成为死代码。dist 产物证实明暗两套变量已在同一个 393KB CSS bundle 里。

**切换的本质 = body 类名 swap**（`theme-dark ctp-mocha-old` ↔ `theme-light ctp-*`），零新 CSS、零重建。

## 三、现状架构（桥接架构）

```
anuppuccin-custom.css（.theme-* / flavor 块，948 行变量定义）
  → --ctp-* → Ob 语义变量（--background-primary 等，3245-3330 行）
  → --ob-*（obsidian-base.css:8-42，33 个，var() 引用 Ob 变量 + 浅色 fallback）
  → --crepe-*（obsidian-base.css:45-73，27 个静态映射）
  → Crepe common 组件（全部 var(--crepe-*) 消费）+ 自有浮层/TOC/toast
```

- CSS 加载顺序（main.ts:4-7）：`@milkdown/crepe/theme/common/style.css` → obsidian-base.css → anuppuccin-custom.css → toc.css。**未加载任何 Crepe 官方主题文件**（frame/nord/classic 均未引），`--crepe-*` 只能由 obsidian-base.css 提供。
- 优先级坑先例：obsidian-base.css:86-94 用 `:where(body.theme-dark)` 零优先级 fallback（注释 83-85：避免压过主题的 `.theme-dark` 单类选择器）。
- TS 侧零颜色硬编码：内联 SVG 全 `currentColor`；仅 `main.ts:64` 启动兜底 `color:red`。

## 五、终态架构（用户拍板，一期完成时达到）

```
主题 = 纯数据：body[data-theme="anuppuccin"].theme-dark { --ob-bg: #1e1e2e; … }（约 40-60 个字面值）
  → --crepe-* 静态映射（保留——它是 Crepe 消费适配，与主题无关）
  → 全部消费方
```

- **废弃**：9080 行 anuppuccin-custom.css、`--ctp-*` flavor 块、Ob 语义变量层、`--ob-*` 内的 `var(--background-*)` 水源。
- **保留**：`--ob-*` 命名空间（它本身就是 Oblet 原生变量体系，改为直接存字面值）、body 类切换、`:where()` fallback 机制。
- 附带收益：剔除约 9000 行外部 CSS，解决 GitHub 语言占比显示 CSS 为主的问题。

## 六、转换器脚本（提前到一期，AnuPpuccin 蒸馏作 dogfood）

开发期工具，进 `scripts/`，不打包：

- **输入**：Obsidian theme.css + 可选 Style Settings 导出 json（如 ref/themes/AnuPpuccin-Custom/oblet-theme.json）
- **解析**：postcss → 按 `.theme-dark`/`.theme-light` × flavor 类取定义域 → var() 链与 `rgb(var(--ctp-x), α)` 求值为字面值
- **映射**：内置「Ob 变量 → `--ob-*`」映射表（权威参照 = 现行 obsidian-base.css 桥接层，拆桥前提取）
- **输出**：
  1. Oblet 原生主题文件（纯变量值）
  2. 适配报告（清单化核心）：`已映射 ✓` / `缺失 ⚠️`（落默认值待微调）/ `未消费 ℹ️`（忽略）/ `意外 ❗`（calc、color-mix、未知引用，列原文待人工）
- **验证**：AnuPpuccin 蒸馏结果须与现行渲染像素级一致（截图 diff 回归）
- 微调后主题文件以人工为准，转换器可重跑增量对比

## 九、风险登记

1. **CM oneDark**（最大技术风险，1C 先行原型验证）
2. **启动闪屏回归**：遮罩链路是性能专题「勿拆」资产，localStorage 镜像不能破坏建窗时序
3. **范围滑坡**：守住白名单固化边界，不做运行时导入
4. **浅色观感**：AnuPpuccin 浅色（latte/rosepine-light）当年用户不满意——死代码复活只是起点，flavor 选定与定制调参才是体验活
5. **GPL-3.0 合规**：AnuPpuccin/Blue Topaz 需保留版权头与 attribution；Minimal/Things 为 MIT。复刻=重写实现，仍需灵感来源声明；`npm run audit` 许可份数检查同步更新
6. **设计文档联动**：v2.0「不做主题系统」需更新为「固化多主题（白名单制），不兼容任意 Obsidian 主题导入」
